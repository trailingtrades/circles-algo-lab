# Apply the 25 Sep 2026 nginx + systemd changes — learn.optionlab.co.in

In short (Hinglish): PR merge hone ke baad, Git Bash mein neeche ke blocks ek-ek karke chalaiye.
Step 3 wahi purana `apply-nginx.sh` hai — khud backup leta hai, `nginx -t` fail ho to khud rollback
kar deta hai. Step 4 sirf systemd unit update hai (2-3 second ka app restart).

**What this round is for:** bot/scraper traffic ko gate ke bahar hi rokna, ek address se flood ko
429 karna, aur Next ke static assets nginx cache se serve karna taaki single Node process sirf
pages render kare — 1 lakh enrolled students की visitor load ke liye headroom.

**When:** after the PR is merged (the nginx files ship from `origin/main`, not the app bundle).
**Who:** Rahul, or Claude from Rahul's machine — the VPS firewall only accepts SSH from Rahul's IPs.
**Time:** about 5 minutes. **Downtime:** none for nginx (graceful reload); step 4 restarts the app
unit once (~3 s, same as every deploy).

## What changes

| What | Before | After |
|---|---|---|
| SemrushBot, AhrefsBot, GPTBot, CCBot, Bytespider, Scrapy, python-requests and other scraper/AI UAs | crawl everything, burn bandwidth on the 9–15 MB course files | 403 on every path of learn.optionlab.co.in (`learn-botguard.conf` map + `if` in academy-site.conf) |
| curl, WhatsApp/facebookexternalhit link previews, TelegramBot, Googlebot/Bingbot | work | still work (deliberately not matched) |
| `/robots.txt` | 404 | 200: landing + `/about/` sales pages indexable, `/smart/` `/funda/` `/winners/` `/one/` `/pro/` disallowed, AI-training bots opted out |
| `/smart` app pages in search results | indexable in principle | `X-Robots-Tag: noindex` on the whole app (public sales page `/smart/about/` unaffected) |
| one address hammering `/smart` | unlimited | 30 r/s + burst 100, then 429 `rate_limited` (sign-in POST limit from 19 Sep stays, both apply) |
| one address opening many parallel downloads | unlimited | 30 concurrent connections, then 503 |
| `/smart/_next/static/*` (hashed JS/CSS/fonts) | every request hits Node | served from nginx cache (`/var/cache/nginx-smart`, 30 d, stale-while-restart) |
| every proxied request + every stage-gate auth_request | new TCP connection to Node each time | reused keepalive pool (`upstream smart_node`) |
| Node file-descriptor cap | distro default 1024 (≈ a few hundred concurrent users) | 65536 (`LimitNOFILE` in learn-smart.service) |

In a browser (2 minutes): sign in at `$H/smart/learn`, open Home and one session — everything loads

## Rollback

nginx: `ssh_ 'bash "$(ls -1d /root/nginx-backup-* | tail -1)/rollback.sh"'` (the backup from step 3).
systemd: remove the `LimitNOFILE=65536` line from `/etc/systemd/system/learn-smart.service`, then
`systemctl daemon-reload && systemctl restart learn-smart`.

## Knobs (documented so nobody hunts later)

| Symptom | Knob |
|---|---|
| a whole classroom on one Wi-Fi sees 429s on page loads | `learn-botguard.conf`: `rate=30r/s` → `60r/s`; `smart-app.conf`: `burst=100` → `200`; reload |
| a legit tool you run is 403'd | remove its token from the `map` in `learn-botguard.conf`; reload |
| classroom sign-ins see "Too many attempts" | unchanged from 19 Sep: `burst=10` → `40` on the three auth locations + `IP_PER_MIN` in `src/lib/auth/rateLimit.ts` |
| cache suspected stale after a weird deploy | `ssh_ 'rm -rf /var/cache/nginx-smart/* && systemctl reload nginx'` (hashed filenames make this almost never needed) |
